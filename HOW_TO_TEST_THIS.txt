HOW TO TEST THIS PROJECT
==========================================

Hi! This is the Fault Reporting Service for our Cloud Computing group
project. Everything in this file is self-contained: you do not need to
ask me (or anyone) for a password, a key, or anything else. Every
value you need, you create yourself as you go.

Do your assigned part below, take the screenshots it asks for, and
send them back to me along with anything that was confusing or didn't
work exactly as described, that's useful information too, not a
complaint.


PART 1 - Basic setup (everyone does this first)
---------------------------------------------------

1. Install Docker Desktop: https://www.docker.com/products/docker-desktop/
   This can take 10-15 minutes and may ask you to restart your computer.
   Open it afterward and wait until it says it's running.

2. Unzip the project file I sent you anywhere on your computer.

3. Open a terminal in that folder.
   Windows: open the unzipped folder in File Explorer, click the
   address bar, type "cmd", press Enter.
   Mac: open Terminal, type "cd " (with a space), drag the folder in,
   press Enter.

4. Start it:
       docker compose up --build

   Wait for it to settle down (a minute or two the first time). Leave
   this terminal window open.

5. Open in your browser: http://localhost:8080/
   You should see "Fault Reporting Service" with a form.


PART 2 - Submit and look up a ticket (everyone does this)
---------------------------------------------------------------

1. Fill in the "Report a fault" form with anything realistic and
   click Submit report. You should see a ticket ID appear.
2. Copy that ticket ID into the "Look up a ticket" box below and
   click Look up. You should get the same details back.

PART 3 - Test real email notifications (only if this is your task)
--------------------------------------------------------------------------

This proves the system can actually email someone when a fault is
reported, not just simulate it.

1. Go to https://resend.com and sign up (free, no credit card needed
   for the free tier).
2. Once signed in, find "API Keys" in their dashboard and create one.
   Copy it, it starts with "re_".
3. Stop the running project (Ctrl+C in its terminal, or close it).
4. In the unzipped project folder, find the file named ".env.example".
   Make a copy of it in the same folder and rename the copy to ".env"
   exactly (no ".txt" at the end, note the leading dot).
5. Open ".env" in a text editor (Notepad is fine). Find these two
   lines and fill them in:

       NOTIFY_EMAIL_API_KEY=re_paste_your_key_here
       NOTIFY_EMAIL_TO=your_own_email_address_here

   Use your own email address for NOTIFY_EMAIL_TO so you can check
   you actually received something. Save the file.
6. Start the project again:
       docker compose up --build
7. Go back to http://localhost:8080/ and submit a report.
8. Check the email inbox you entered. You should receive an email
   about the ticket within a few seconds.

   >>> SCREENSHOT the email you received, and the ticket response
       on screen. <<<

If no email arrives after a minute, check the terminal window for a
line containing "notify_failed", it will tell you what went wrong
(usually a typo in the key or address).


PART 4 - Test maintenance status updates (only if this is your task)
----------------------------------------------------------------------------

This proves the maintenance team can mark a ticket as being worked on,
instead of it sitting as "open" forever.

1. Make up your own secret key, any random text at least 10 characters
   long is fine, for example: my-own-test-key-2026
2. Stop the running project if it's running (Ctrl+C in its terminal).
3. Create a ".env" file the same way as Part 3, step 4, if you haven't
   already (copy .env.example, rename to .env).
4. Open .env and find this line, then fill in the key you made up:

       MAINTENANCE_API_KEY=my-own-test-key-2026

   Save the file.
5. Start the project:
       docker compose up --build
6. Go to http://localhost:8080/ and submit a fault report, as in
   Part 2. Copy its ticket ID.
7. Scroll down to the "Maintenance team: update a ticket's status"
   section.
8. Enter the ticket ID, choose "In progress" from the dropdown, and
   enter the exact same key you made up in step 1 into the
   "Maintenance key" field. Click Update status.
9. You should see the ticket come back with its status now showing
   "in_progress".
10. Try it again, this time entering the WRONG key on purpose. It
    should be refused.

    >>> SCREENSHOT both results, the successful update and the
        refused one. <<<
