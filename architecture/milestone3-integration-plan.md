# Milestone 3 Integration Plan

Required Milestone 2 submission item (§5.6): *"Milestone 3 integration
plan and updated role allocation."* Work period: 21 Sep – 4 Oct 2026.

## What "integration" means for this project

Unusually for this handbook's Milestone 3 (§6), the vertical slice
already runs end-to-end — it was built ahead of schedule as a head start
(per the Milestone 1 plan). So Milestone 3 here is not "build the slice,"
it is **§6.2's actual required activities**: prove it on a clean machine,
trace a correlation ID, and get a second team member to independently
reproduce it. That reframes the plan below.

## Milestone 3 task plan (§6.2 required activities, mapped to owners)

| # | Required activity (§6.2) | Concrete task in this repo | Owner (role) | Target |
|---|---|---|---|---|
| 1 | Create the environment from repo instructions on a clean machine | A teammate other than the one who's been running it clones the repo fresh and runs `docker compose up --build` from `README.md` alone, no extra help | Cloud platform & security lead | Early in the M3 window |
| 2 | Submit one valid event, retain the correlation ID | Run `scripts/smoke_test.sh`, capture the `correlation_id` from the E1 response | Data & observability lead | Same session |
| 3 | Trace that ID through the logs | `docker compose logs app \| grep <correlation_id>` — show `accepted` → `notified`/`notify_failed` → `persisted` all sharing the ID | Data & observability lead | Same session |
| 4 | Submit one invalid event, show it's rejected safely | Re-run smoke test's E4/E5 cases, confirm no new row in `tickets` table for those requests | Function/application developer | Same session |
| 5 | Run one automated + one end-to-end test | `pytest -v` (automated) + `scripts/smoke_test.sh` (end-to-end) | QA, cost & documentation lead | Same session |
| 6 | **Second team member independently reproduces the slice** (§6.5 acceptance: "at least two members have reproduced") | A different teammate repeats steps 1–5 on their own machine, from the README alone, no live help | Any second member | Before the clinic |
| 7 | Record blockers / amendments | Log anything that broke or was unclear in `architecture/decisions/` as a new numbered ADR entry if it changes a prior decision | Architecture & integration lead | Ongoing |
| 8 | Update README so it's reproducible by someone who wasn't in this conversation | Sanity-check `README.md`'s Docker instructions read correctly with zero implicit context | QA, cost & documentation lead | Before submission |

## Evidence pack additions expected from this pass

- Screenshot/log excerpt of a **second member's** clean-machine startup and
  correlation-ID trace (§6.3 E1–E3, E6) — this is the one piece of
  Milestone 3 evidence that cannot be generated by one person working
  alone, since §6.5's acceptance checklist explicitly requires it: *"At
  least two members have reproduced the slice."*
- Any amendment to the architecture, logged as ADR `0002-...` if something
  the team learns during reproduction changes a Milestone 2 decision.
